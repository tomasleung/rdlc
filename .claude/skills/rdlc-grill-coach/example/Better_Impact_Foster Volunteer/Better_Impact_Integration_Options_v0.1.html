01Confirmed: no scheduling or automation exists in Better Impact, at any tier

Checked directly against Better Impact's own "Comprehensive Guide to Reporting." Every report — Standard or Raw Data, Hours, Schedule, or Personal Profile — runs only when a person manually clicks to run it, and exports only when a person manually clicks to export it. "Saving" a report saves its filter/column configuration for reuse; it does not run it, export it, or email it on any schedule. There is no recurring export, no scheduled email delivery, no SFTP drop — nothing resembling ShelterBuddy's automated API-fed silver-layer pipeline.

What this means The "no-cost, like SB" option doesn't exist. Whatever path BC SPCA takes, someone or something has to manually trigger the pull — either a person on a recurring human schedule, or our own code calling the API on an automated schedule. There is no third way where Better Impact does the scheduling for us.

03Two realistic integration paths

Option A — Manual periodic export No added cost, if current tier allows Raw Data Reports

HowA person logs into Better Impact on a recurring cadence (e.g. weekly), manually runs the Personal Profile Raw Data report, exports to CSV/XLSX, and hands it to the Data Team for ingestion into Fabric.
Gives usCurrent status per volunteer, same fields as the API (status, status reason, last-change date) — still no built-in history.
Can reconstruct history?Yes, but only through human discipline — if every weekly export is kept, Data Team can stitch together a pseudo-history over time (same periodic-snapshot idea from the companion discovery doc). Miss a week and that week's state is gone permanently, since Better Impact itself never kept it either.
Real riskDepends on a person reliably running and handing off the export every cycle — the exact same "administrative reliability" problem Lindsay's brief already flagged for status archiving. This isn't a lesser-risk option, it's the same risk moved to a different task.

Option B — API-based automated pull Likely requires Impact tier (cost to confirm)

HowA Fabric pipeline (or similar) calls the Better Impact REST API on an automated schedule (e.g. nightly), using the updated_since filter to pull only changed profiles, landing results the same way ShelterBuddy's API feed already does.
Gives usThe exact same fields as Option A (current status + last-change date) — the API does not expose more data than the Raw Data Report. No history either way.
Real benefit over AReliability and no manual labor, not more data. Removes the human-discipline failure point — the pull happens whether or not anyone remembers. That is the entire value proposition of paying for this tier, if an upgrade is in fact required.
CostUnconfirmed — Better Impact's pricing is "Contact Us" only, no published figures. Needs a direct conversation with Better Impact sales once the current tier is confirmed.
The actual decision, once facts are in Since neither option returns history, the choice between A and B is really "do we trust a recurring manual export forever, or pay for automation that removes that single point of failure" — not "which one gives us better data." If BC SPCA is already planning to upgrade to Impact tier for other reasons (SSO, advanced reporting), the marginal case for the API specifically is just automation reliability, worth knowing before that conversation with Better Impact sales.
