01 · Executive summary

The organization uses Microsoft Fabric as its enterprise analytics platform to support reporting, business intelligence, operational decision-making, and data products.

Some source systems contain sensitive information such as:

  • Volunteer names
  • Employee names
  • Email addresses
  • Phone numbers
  • Animal foster information
  • Operational records
Guiding principle
Sensitive data may be stored within Microsoft Fabric when there is a legitimate business requirement. The objective is not to eliminate all sensitive data, but to ensure it is protected through appropriate security, governance, and access controls.

Microsoft Fabric provides built-in security capabilities including:

  • Encryption at rest
  • Encryption in transit
  • Microsoft Entra ID authentication
  • Role-based access control (RBAC)
  • Data governance and auditing capabilities

These security features are enabled and managed by Microsoft as part of the Fabric platform.

02 · Why we store sensitive data

Sensitive data is retained only when required for business operations, reporting, analytics, compliance, or data quality purposes.

Examples

  • Operational reporting — volunteer participation reporting, foster program reporting, employee activity reporting
  • Data integration — matching records across systems, eliminating duplicate records, historical tracking
  • Data quality — record validation, audit and reconciliation activities
Without storing some identifying information, it may not be possible to: link records accurately, validate operational processes, or produce required business reports.

04 · Microsoft Fabric security controls

Microsoft Fabric includes several built-in security controls.

Encryption

Microsoft automatically encrypts data at rest and data in transit. This protects information from unauthorized access during storage and transmission.

Authentication

Microsoft Fabric uses Microsoft Entra ID (Azure Active Directory). Users must authenticate before accessing Fabric resources.

Access control

Fabric supports workspace permissions, item permissions, OneLake security, and role-based access control. Access can be restricted to specific users and groups.

Auditing and governance

Fabric provides activity monitoring, data lineage, security governance features, and sensitivity labels. These features support compliance and auditing requirements.

06 · Sensitive data handling rules

Rule 1 — Business need required

Sensitive information must only be stored if there is a legitimate business purpose. Questions to ask: Why do we need this data? Who uses it? Can the decision be made without it?

Rule 2 — Minimum necessary data

Only collect and retain the minimum amount of sensitive information required.

Preferred: Volunteer ID, Hours, Centre  ·  Avoid (unless operationally required): Volunteer Name, Address, Phone

Rule 3 — Restrict access

Sensitive information should only be accessible to Data Developers, Data Analysts, and Approved Business Owners. General report users should not have direct Lakehouse access.

Rule 4 — Remove sensitive data from Gold

Where possible: replace names with IDs, aggregate metrics, remove unnecessary personal information. Gold datasets should be optimized for reporting rather than operational record storage.

Rule 5 — Review regularly

Data owners should periodically review sensitive fields, user access, and business requirements.

07 · Security risks

Risk 1 — Unauthorized access

An individual gains access to data they are not authorized to view.

Mitigation: Entra ID authentication, workspace security, principle of least privilege

Risk 2 — Overexposed reporting

Sensitive fields accidentally appear in reports.

Mitigation: Gold-layer curation, report review process, data model validation

Risk 3 — Excessive permissions

Too many users have Contributor or Member access.

Mitigation: Limit workspace roles, use security groups, perform access reviews

Risk 4 — Data export

Authorized users export sensitive information outside Fabric.

Mitigation: Restrict export permissions, apply governance controls, monitor usage

Risk 5 — Human error

Incorrect sharing or publishing of reports.

Mitigation: User training, governance review, change management process

09 · Microsoft Purview and sensitive data governance

The organization uses Microsoft Fabric together with Microsoft Purview capabilities to identify, classify, monitor, and protect sensitive information throughout the analytics platform.

The goal is to ensure that sensitive data is identified, properly classified, accessed only by authorized users, and governed according to organizational policies.

How Purview helps

Sensitive data discovery

Purview can help identify common sensitive information patterns such as names, email addresses, phone numbers, government identifiers, and financial information. This allows data teams to understand where sensitive information exists within the Fabric environment.

Data classification

Purview enables data classification through sensitivity labels.

LabelDescription
PublicApproved for external sharing
InternalInternal business use
ConfidentialContains personal information
RestrictedHighly sensitive information

Classification improves visibility and governance across the platform.

Data lineage

Purview and Fabric lineage capabilities help answer:

  • Where did this data originate?
  • Which reports use this data?
  • Who owns the data?
  • What downstream systems are impacted?

This improves auditability and change management.

Can Purview prevent users from seeing sensitive data?

Partially. Purview helps identify and classify sensitive data, but it is not the primary mechanism used to prevent access.

Access prevention should be implemented using:

  • Microsoft Entra ID security groups
  • Fabric workspace permissions
  • OneLake security
  • Item permissions
  • Row-Level Security (RLS)
  • Column-Level Security (CLS)
  • Report access controls

These technologies determine whether a user can view or access data.

Data Loss Prevention (DLP)

Purview supports Data Loss Prevention (DLP) capabilities that can help organizations identify and monitor the movement of sensitive information. Fabric also integrates with sensitivity labels and governance controls. Examples include:

  • Flagging datasets containing personal information
  • Alerting administrators to policy violations
  • Applying sensitivity labels
  • Monitoring risky activities involving sensitive data

These controls help reduce the risk of accidental exposure.

Recommended governance model

Layer 1 — Discovery

Purview identifies sensitive fields such as Volunteer Name, Volunteer Email, Employee Name, and Personal Contact Information.

Layer 2 — Classification

Apply sensitivity labels: Internal, Confidential, Restricted.

Layer 3 — Access control

Use Fabric security to limit access: Bronze/Silver → Data Team; Gold → Report Developers; Reports → Business Users.

Layer 4 — Monitoring

Use audit logging and governance tools to periodically review access permissions, sensitive data usage, data exports, and policy compliance.

Example: volunteer data

Purview classification: Confidential

Bronze

Contains: Volunteer Name, Email, Volunteer ID

Access: Data Team only

Purview classification: Internal

Gold

Contains: Volunteer ID, Volunteer Hours, Centre

Access: Business Users

In this approach, the sensitive fields remain protected while still enabling reporting and analytics.

10 · Conclusion

Sensitive data can be stored within Microsoft Fabric when required for legitimate business purposes. Microsoft Fabric provides enterprise-grade security through encryption, authentication, access control, governance, and auditing capabilities.

The primary objective is not to eliminate sensitive data entirely, but to:

  • Store only what is necessary.
  • Restrict access appropriately.
  • Remove sensitive information from reporting layers whenever possible.
  • Maintain governance and accountability over data usage.

Following these principles allows the organization to balance operational requirements, analytics needs, and privacy obligations while leveraging Microsoft Fabric as a secure enterprise analytics platform.
