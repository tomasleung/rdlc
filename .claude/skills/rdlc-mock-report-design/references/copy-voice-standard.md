# Copy and voice standard

**Source:** `04-powerbi-project/Design Guide/BC SPCA style guidelines.pdf` ("Style guidelines — Language, voice and copy standards," last updated September 2026). This is BC SPCA's real, official writing/voice guide — it governs the *text* any mock report generates (headlines, insight callouts, labels, narrative), not visual design. Apply it to every piece of generated copy.

## Mechanical rules
- Sentence case in headlines/headings (only first word + proper nouns capitalized); numbers/symbols normally spelled out in body text are printed as symbols in headlines (8, %, $8M).
- One space after sentence punctuation. No double hard returns.
- Exclamation points: sparingly, at most one per page.
- Avoid ALL CAPS except where already established for titles (e.g. this project's eyebrow/badge labels).
- No Oxford/serial commas (exception: scientific/policy submissions — not applicable to a report mock).
- Numbers 1–9 spelled out, 10+ as figures, with standard exceptions (decimals, ages after a name, measurements, addresses, sentence-initial numbers, specific dates). Percentages spelled out as "per cent" in body copy — but note this project's existing dashboards already use the `%` symbol in headline/KPI contexts, which the guide's own headline exception explicitly permits.
- Hyphenate compound modifiers before a noun ("cost-efficient manner"); don't hyphenate the verb form ("costs were cost effective"); don't hyphenate adverbs ending in "-ly".

## Terminology
- "Owner" is now the Society's standard term (not "animal guardian," though that remains acceptable in formal settings).
- Never use the internal phrase "Large Scale Animal Intake" / "LSAI" in anything public-facing or stakeholder-facing — not easily understood outside the organization. Flag if an Insight Specification register ever names a KPI using this internal shorthand.
- "More than" for quantity, "over" for location/physical position.
- Animal pronouns: "who," not "which"/"that," in reference to animals. "They/them/their" when sex is unknown.
- "Pets" is fine for public-facing, non-scientific communication (even though not used internally) — a report mock aimed at program owners/directors is internal, so prefer "animals" over "pets" unless the audience is explicitly external.

## What this means for a report mock specifically
- Any narrative/insight-callout text the mock invents (even as illustrative placeholder copy) should already read in the Society's real voice — sentence-case headlines, no stray exclamation points, "who" not "that" for animals, hyphenation rules applied — so a reviewer isn't distracted by voice issues unrelated to the actual layout/UX decision being reviewed.
- This does not relax or override `rdlc-data-analysis`'s interpretation-boundary rules (no performance/causal language unless the BRD authorizes it) — voice and epistemic discipline are separate, both apply simultaneously.
